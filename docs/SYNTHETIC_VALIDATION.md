# 합성 자료로 Mac·Windows 실기 확인하기

이 키트는 T01 계산 정확성, T06 시험지 가져오기, 실제 PC 사용 확인을 돕는 **합성 검증 자료**입니다. 학생 이름·학번·반/번호는 모두 `합성`으로 표시한 독립 가짜 값입니다. 실제 학생자료나 기존 시험지를 읽거나 복제하지 않습니다. 합성 검사 통과만으로 학교 PC 검증·교사 확인·제품 전체 완료를 대신하지 않습니다.

## 키트 생성

개발 환경이 준비된 저장소에서 아래 명령을 실행합니다. 새 설치나 다운로드는 실행하지 않습니다. 이미 있는 출력 폴더는 파일 하나도 바꾸지 않고 중단합니다. 출력 경로나 상위 경로가 symlink/junction이면 중단합니다.

Mac:

```bash
.venv/bin/python -B build_scripts/generate_synthetic_validation_kit.py --output out_test/synthetic-validation-kit-01
```

Windows:

```bat
.venv\Scripts\python.exe -B build_scripts\generate_synthetic_validation_kit.py --output out_test\synthetic-validation-kit-01
```

실행에 필요한 `openpyxl`, `numpy`, `matplotlib`, `pypdf`는 현재 개발 의존성에 포함됩니다. PDF에는 저장소의 `assets/fonts/NanumGothic.ttf`를 사용합니다. 렌더 캐시는 생성 중에 새 출력 폴더의 임시 위치를 사용합니다. 생성에 실패했다면 그 폴더를 성공 키트로 사용하지 말고 오류를 확인한 뒤 새 이름으로 생성하세요.

`out_test/`는 이미 Git에서 제외되어 있습니다. GitHub에는 생성 코드·테스트·이 안내만 올립니다. 생성된 XLSX/HWPX/PDF/학생 JSON은 커밋하지 않습니다. 같은 키트를 두 PC에서 사용하려면 승인된 방식으로 키트 폴더 전체를 옮기고 파일 해시를 대조하세요. 생성 스크립트는 복사나 업로드를 실행하지 않습니다.

## 파일과 지원 입력 형식

| 파일 | 현재 앱에서 확인할 입력 형식 |
|---|---|
| `합성_정오표.xlsx` | 활성 시트. `반/번호` 열에 학번, 다음 열에 반/번호, `성명` 열에 이름. 숫자 문항번호 열과 그 아래 정답·배점 행, 다음 행부터 응답. `.`은 정답, 숫자는 오답 선택지. `선택형점수`·`서답형점수`·`기타점수`·`과목총점` 포함 |
| `합성_문항정보표.xlsx` | `문항번호`·`내용영역`·`성취기준`·`난이도`·`배점`·`정답` 머리글. 다음 행에 어려움/보통/쉬움, 그 아래 문항. `서답형 문항` 구분 행 이후 서답형으로 처리 |
| `합성_수행평가.xlsx` | 선택 입력. `반/번호` 다음 열에 학번, `성명`, `합 계`, 영역명 안의 `(만점 15.00,15.00%)` 같은 표기. 합계/만점합×100으로 수행점수 환산 |
| `합성_시험지.txt` | UTF-8 한국어, 번호 `1.`·`2.`·`[서답형 1]`, 배점 `[37.5점]`·`[25점]`, 선택지 ①~⑤ |
| `합성_시험지.hwpx` | 같은 한국어 내용을 담은 `Contents/section0.xml` 최소 HWPX 컨테이너. 앱의 내장 문단 추출을 확인하는 입력이며, 한글 앱에서의 편집·인쇄 호환성을 보증하는 완전한 한글 문서 템플릿은 아님 |
| `합성_시험지.pdf` | 같은 한국어 시험지의 텍스트 PDF. 로컬 NanumGothic 내장 폰트 사용. 스캔·이미지 PDF나 복잡한 2단 편집 검증은 포함하지 않음 |
| `합성_계산기_검토안.json` | 계산기 작업 schema `version: 1`, 검토안 2개, 활성 검토안 2, 문항 2개, 직접 %와 O/X 배열 함께 포함. 실제 학생 목록 없음 |
| `expected.json` | 제품 함수 결과에서 역생성하지 않은 수기 상수·계산 근거·한계 |
| `validation.json` | 생성 직후 실제 XLSX 로더·시험지 파서·계산 함수를 상수와 대조한 결과. `status: passed`여야 성공 |
| `manifest.json` | 앱 버전과 생성 파일별 SHA256. manifest 자신을 제외한 모든 생성 파일 포함. 생성 시각·PDF/XLSX 메타데이터 때문에 새로 만든 키트끼리 파일 해시가 다를 수 있으나 기대 산술값은 동일 |

이 형식은 현재 로더가 지원하는 한 가지 NEIS 유사 배치를 확인합니다. 모든 학교·과목·다운로드 양식의 호환성을 증명하지 않습니다. 정오표의 선택/서답/총점은 **입력에 저장한 값**이며, 앱이 서답형 답안을 자동 채점하는 검사가 아닙니다.

## 1. 정오표·문항정보표와 수행평가

1. 검증할 배포 후보 앱을 실행하고 버전·운영체제·CPU·후보 파일 SHA256을 기록합니다. 기존 설치 앱의 결과와 구분합니다.
2. 왼쪽 입력 패널에서 **학생답 정오표**에 `합성_정오표.xlsx`, **문항정보표**에 `합성_문항정보표.xlsx`를 지정합니다.
3. 분할점수를 A=90, B=80, C=70, D=60, E=40으로 맞추고 수행평가를 적용하지 않은 상태에서 **분석 실행**을 누릅니다.
4. 학생 4명, 선택형 2문항·서답형 1문항, 배점 37.5·37.5·25점, 총점 100점을 확인합니다.
5. 학생 순서와 점수, 전체 평균, 문항 정답률을 아래 표와 대조합니다.
6. 수행평가 파일에 `합성_수행평가.xlsx`를 지정하고 수행평가 적용, 지필 60%·수행 40%로 다시 분석합니다. 이름·학번 연결과 환산점수를 확인합니다.

| 합성 학번 | 지필점수 | 수행 원점수/40 | 수행 100점 환산 | 지필 60%+수행 40% | 지필 성취도 |
|---|---:|---:|---:|---:|---|
| 합성-001 | 100 | 40 | 100 | 100 | A |
| 합성-002 | 50 | 20 | 50 | 50 | E |
| 합성-003 | 37.5 | 10 | 25 | 32.5 | 미도달 |
| 합성-004 | 0 | 0 | 0 | 0 | 미도달 |

수기 평균은 지필 `(100+50+37.5+0)/4 = 46.875`, 수행 적용 `(100+50+32.5+0)/4 = 45.625`입니다. 선택형 두 문항은 각각 4명 중 2명이 정답이므로 각각 50%입니다. 학생 목록 정렬이 달라졌다면 학번으로 대조하세요.

## 2. 시험지 문항 가져오기

1. **예상정답률** 탭에서 기존 작업을 저장한 뒤 앱 상단 **자료 → 시험지에서 문항 가져오기**를 선택합니다.
2. 먼저 `합성_시험지.hwpx`, 이어서 `합성_시험지.pdf`를 각각 읽어 봅니다. 각 시도 전에 필요하면 계산기 작업을 저장합니다.
3. 선택형 1번 37.5점·선택형 2번 37.5점·서답형 1번 25점, 합계 100점인지 확인합니다. 선택형 보기 수는 각각 5개입니다.
4. 문항 번호·유형·배점을 교사가 확인한 뒤 계산기로 보내고 저장·불러오기를 확인합니다. `합성_시험지.txt`는 내장 텍스트 추출 대조용이며, UI의 파일 필터가 보여 주는 지원 확장자를 우선 사용합니다.

**HWP 바이너리는 이 키트에서 생성·검증하지 않습니다.** 변환기 부재 검사는 기존 프로젝트 테스트에 있지만 실제 HWP 읽기 성공 증거와 구분합니다. 학교 PC에 이미 한글이 있다면 합성 시험지만 직접 작성하여 HWP로 저장한 후 확인할 수 있습니다. kordoc이 없다는 안내가 나오면 새 설치를 진행하지 말고 한글에서 HWPX 또는 텍스트 PDF로 저장해 다시 읽으세요. 새 설치가 필요한 경우 별도 승인 대상입니다. 스캔 PDF는 글자 추출이 지원되지 않을 수 있습니다.

## 3. 소수 배점·직접 %·검토안 저장 확인

1. **예상정답률 → 작업 불러오기**에서 `합성_계산기_검토안.json`을 엽니다.
2. 검토안이 합성 검토안 1·2이고, 활성 검토안은 2인지 확인합니다. 문항 배점은 1.5점·3.25점, 합계 4.75점입니다.
3. 1번 C 직접값 63.25%, A 100%, E 0%가 소수나 경계값을 잃지 않았는지 확인합니다. 검토안 1의 B=82.5%, 검토안 2의 B=77.5%도 각각 확인합니다. O/X 인원 표시와 직접 %는 별개이며 직접 %가 우선합니다.
4. 점수 비교에서 아래 값을 확인합니다. 검토안별 비율의 평균을 먼저 구한 뒤 배점 가중합을 계산합니다.
5. 새 파일 이름으로 **작업 저장**, 새 작업을 열고 다시 불러오기를 합니다. 두 검토안·활성 검토안·배점·63.25%·0%·100%가 유지되는지 확인합니다.
6. **NEIS 입력표**와 검토표 XLSX를 새 이름으로 저장하고 원값과 5% 반올림 값을 대조합니다. 실제 NEIS에 입력하지 않습니다.

| 수준 | 문항별 원점수 | 100점 환산 | NEIS 반올림 원점수 | NEIS 100점 환산 |
|---|---:|---:|---:|---:|
| A | 4.75 | 100 | 4.75 | 100 |
| B | 3.6375 | 약 76.578947 | 3.5625 | 75 |
| C | 2.73625 | 약 57.605263 | 2.85 | 60 |
| D | 1.6625 | 35 | 1.6625 | 35 |
| E | 0.4875 | 약 10.263158 | 0.475 | 10 |

예를 들어 C는 `1.5×0.6325 + 3.25×0.55 = 2.73625`, 100점 환산은 `2.73625/4.75×100`입니다. NEIS는 같은 선택형·보통 묶음의 가중평균 약 57.605263%를 60%로 반올림하므로 `4.75×0.60=2.85`입니다. 원값과 NEIS값의 차이가 기대 동작입니다.

## 결과 기록과 완료 판단

Mac과 Windows 각각 날짜·OS/CPU·앱 버전·소스 커밋·후보 SHA256·키트 manifest 해시·검사 항목·실제 결과·실패 메시지를 기록합니다. 생성 시의 자동 대조 결과와 사람이 설치 앱을 눌러 확인한 결과를 별도로 기록하세요. 이 키트로 확인하지 못한 실제 HWP, 복잡한 학교 파일 양식, 작은 화면 사용, 교사 업무 적합성은 미검증으로 남깁니다. 학교 PC나 교사 확인이 없으면 전체 Goal 완료로 표시하지 않습니다.

## 개발 소스의 격리 분석·내보내기 확인

개발 환경에서 실제 창을 여는 별도 검사입니다. 입력 파일을 인자로 받지 않고 새 합성 키트를 직접 생성합니다. 파일 선택·대화상자 응답만 통제하며 실제 MainWindow 분석 버튼과 CSV·근거 엑셀 작성 경로를 사용합니다. 기존 설정·포트폴리오·설치 앱을 사용하지 않습니다.

```bash
.venv/bin/python tests/manual_analysis_flows.py --run --output out_test/native-analysis-01
```

Windows 개발 환경에서는 Python 경로를 `.venv\Scripts\python.exe`로 바꿉니다. Windows에서 이 명령을 실제 실행한 결과는 아직 확인하지 않았습니다. 새 출력 폴더의 `ANALYSIS_QA.json`과 PNG를 읽어 판단하며 기존 폴더는 덮어쓰지 않습니다. 검사는 지필/수행 60·40, 잘못된 입력 뒤 기존 분석 유지, 가명 CSV 4개·근거 XLSX, 저장 취소, 실명 거절, 합성 실명 승인 때 수식 모양 이름을 문자로 저장, 격리된 해시 snapshot과 입력 원본 보존을 확인합니다. 예측–실측 보고서·Windows Excel·실제 설치와 교사 확인은 별도 검증입니다.

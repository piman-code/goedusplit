## 최종 목표

NEIS 정오표·문항정보표 기반 성취평가 분석과 **추정분할점수 설계**를 인터넷 없이 교사 PC에서 안전하게 쓰는 Windows·macOS 앱.
시험지 오류 점검과 외부 AI는 교사가 명시적으로 켜는 선택 기능으로만 붙인다.

## 1단계 이후 추가 작업 (2026-09-24)

- **계산기 '작업 저장'·'CSV 내보내기'가 데스크톱 앱에서 파일을 남기지 않던 문제 확인·수정.**
  - 재현: 실제 Qt WebEngine(offscreen, 격리 프로필, 합성 자료)에서 두 버튼 모두 `downloadRequested`는 오지만 파일 0개.
    앱이 요청을 받아 주지 않아 Qt가 취소했다. 1.0.1 이전부터 있던 문제로 보인다.
  - 수정: `_connect_spliter_downloads`(프로필당 한 번 연결) → 저장 위치를 묻고 `accept()`. 계산기 페이지가 아닌 요청과 취소는 거절.
    저장된 CSV는 수식처럼 보이는 칸만 `'`로 막는다(숫자 `-5`는 그대로, BOM·줄바꿈 유지).
  - 수정 후 같은 재현: 두 파일 모두 고른 위치에 생성, 작업 JSON에 합성 문항 18개 보존.
  - 미검증: 계산기 '작업 불러오기'(파일 선택)를 Qt에서 왕복해 보는 것, Windows.
- 포트폴리오 스냅샷(version 2): 학번·반/번호·이름 대신 `student_hash`(HMAC-SHA256, 24자)만 저장.
  키는 이 PC 앱 설정 `privacy/portfolio_hash_key`(32바이트, 처음 쓸 때 생성). 예전 version 1 실명 스냅샷도 같은 해시로 연결해 읽는다.
  화면의 이름·반/번호는 지금 불러온 분석 자료에서만 되찾고, 없으면 `학생#abc123`. 설정 초기화·다른 PC면 이전 스냅샷과 연결이 끊긴다.
  이 Mac의 기존 스냅샷은 0개였다. 다른 PC의 예전 실명 스냅샷 파일은 그대로 실명이 남아 있다.
- '자료 > 가명 ↔ 실명 확인': 현재 분석의 가명·학급·반/번호·이름을 화면 창에만 보여 준다. 파일 저장 없음.
- 테스트: Python 85, Node 43 통과. 새 보호 기능(CSV 점검, 해시 저장, 다른 페이지 거절)을 끄면 테스트가 실패하는 것 확인.

## 2단계: 예측-실측 보정 리포트 (2026-09-24, 맥)

- 진입: 예상정답률 탭 '자료 > 예측-실측 비교'. 계산기의 현재 작업(검토안 평균)을 분석 결과와 비교한다.
  시험 전 작업을 '작업 불러오기'로 연 뒤 쓰는 흐름이다.
- 계산: `app/calibration.py`(순수 함수, `tests/test_calibration.py` 7개).
  - 실측 = 각 성취수준 하위 1/3(최소 1명) 학생 정답률. 교사는 최소능력자를 예측하므로 수준 전체 평균과 비교하면 늘 비관적으로 보인다.
    수준 전체 평균은 칸 툴팁과 엑셀에 참고로 둔다.
  - 선택형은 문항별, 서답형은 정오표에 학생별 총점만 있어 묶음(배점 가중 예측 vs 서답 총점 비율)으로 비교.
  - 요약: 수준별 평균 차이(실측-예측), 난이도별, 15%p 이상 칸 수, 경계별 100점 환산 예측 vs 실측. 학생 5명 미만 수준은 '참고만'.
  - 순환성: 실제 수준은 적용한 분할점수로 나눈 결과라 참고 자료로만 표시.
- 엑셀 저장: 요약·문항별 시트, 학생 식별정보 없음(테스트로 확인).
- 확인: 실제 Qt로 비교 창을 그려 보았다(계산기 웹 엔진은 빼고 기존 작업 가져오기 경로 대신 같은 작업 데이터를 넘김).
  같은 캡처 스크립트에서 분석 자료+계산기 로딩이 멈췄으나, 검증된 재현 스크립트에 분석 자료를 넣으면 정상 로딩되어 스크립트 문제로 판단.
- 미구현: 비교 결과를 다음 시험 기본 기준표에 반영하는 제안(교사 선택 적용). 필요하면 다음 작업.
- 미검증: 실제 시험 자료로 결과가 교사에게 의미 있는지(바탕화면 실제 자료로 사용자가 직접 확인 예정).

## Windows 실기 검증 체크리스트 (사람 작업)

에이전트가 Mac에서 대신할 수 없다. Windows PC에서 합성 자료로 확인한다.

0. CI 첫 실행(push 승인 후): GitHub Actions `Build Windows Distribution`을 `workflow_dispatch`로 실행하면서
   입력 `checkout_ref`에 `work/1.0.3-hardening`을 직접 적는다(기본값 `main`이면 이 브랜치가 아니라 main을 빌드한다).
   소스 감사·Python 테스트·웹 테스트·빌드 감사가 모두 초록인지, 실패하면 어느 단계인지 기록.
1. 빌드: `python -m PyInstaller --noconfirm --clean goedusplit.spec` 성공, `dist\Goedu-Split\Goedu-Split.exe` 실행. 창 제목의 버전이 1.0.3인지.
2. 첫 실행: SmartScreen 안내 문구, 한글 폰트, 창 크기 1280x800·1366x768에서 입력 패널 접기.
3. 불러오기: 한글 경로·공백 있는 폴더의 합성 정오표·문항정보표 불러오기, 분석 실행.
4. 예상정답률 탭: 화면 표시(WebEngine), 소수 정답률 입력, 저장·불러오기, NEIS 입력표 XLSX 저장 후 Excel에서 열기.
   계산기의 근거 학생 표시가 실명 대신 `학생 001` 형식인지, '자료 > 가명 ↔ 실명 확인'으로 실명이 보이는지.
   계산기 '작업 저장'·'CSV 내보내기'를 누르면 저장 창이 뜨고 파일이 생기는지, 저장한 작업을 '작업 불러오기'로 다시 여는지.
5. 결과 CSV(`Ctrl+E`): 확인란을 끈 채 저장 → `학생결과.csv`를 Excel로 열어 한글이 깨지지 않고 첫 열이 `가명 ID`인지.
   확인란을 켜면 경고 창이 뜨고, '아니요'면 아무 파일도 생기지 않는지, '예'면 학번·반/번호·이름이 들어가는지.
6. 근거 엑셀(자료 메뉴): 저장 전 선택 창이 뜨는지, 기본 저장 파일에 실명이 없는지, 실명 포함은 경고 확인 후에만 되는지.
7. 오프라인: 네트워크를 끊은 상태에서 1~6이 동일하게 동작.
8. 결과 기록: 이 파일의 '작업 기록'에 날짜·Windows 버전·항목별 결과를 적는다.
